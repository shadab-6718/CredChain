Technical Approach

CredChain – Progressive, Decentralized and Verifiable Credentials

Core Idea: Store the cryptographic trail on blockchain, keep encrypted documents on decentralized storage, and enable secure, consent-based access.

Issuer

(University / Land Board)

Issues progressive milestones & final credentials

Holder

(Student / Landowner)

Controls sovereign access to documents & consent

Verifier

(Employer / Bank / Govt)

Verifies credentials & views trail with consent

Admin

(Platform Governance)

Onboards & manages verified issuing institutions

1
Issue Credential
  • Upload document PDF
  • Select type (milestone/final)
  • Generate QR commitment
➔
2
Store Document
  • Encrypt document (client-side)
  • Upload to IPFS
  • Obtain content CID
➔
3
Record on Blockchain
  • Store on-chain record
  • Link previous event (trail)
  • Save IPFS Content CID
  • Set status (VALID)
➔
4
Verify / Access
  • Scan QR / Submit document
  • Fetch record & audit trail
  • Request time-boxed access
  • Decrypt & inspect with consent
Decentralized Storage
  • Stores AES-256 encrypted documents
  • Returns tamper-proof Content ID (CID)
  • Zero raw plaintext stored
Blockchain Network
  • Polygon Amoy consensus (80002)
  • Stores milestone linked-list trail
  • Manages immutable revocation
  • Enforces time-boxed expiration
Backend API
  • Handles business logic & auth
  • Streaming SHA-256 calculation
  • Brokers verifier access handshake
  • Connects with Supabase RLS
Frontend (Web App)
  • Role dashboards (Issuer/Holder/Verifier)
  • Web3 Ethers.js integration
  • Visual milestone trail inspector
  • Time-box consent manager
Security & Privacy
Client-side AES-256 encryption Zero PII on blockchain Holder-controlled sovereign consent Tamper-proof & transparent audit trail
